# 费曼导读 · 四对齐机制（视频验收分仓版）v1.0

> **English abstract** — Feynman Guide Four-Axis Alignment applied to AI-video acceptance. The four axes here are: *result* (a measured sampling-reduction multiple with a stated base rate, verifier Se/Sp, and seed), *mechanism* (PPV under low base rates — why specificity decides everything), *code* (one command, fixed seed 20261016, stdlib only, exit 0), *direction* (the safety layer never trades away, G8 out of scope). Fourteen production-adjacent examples, six analogies (AQL sampling, Wald's SPRT, Shewhart SPC, error-cost asymmetry, Goodhart, Lindy), and a sourced reference list. Numbers below are hand-checkable.
>
> 本文是分仓的导读契约。它与主仓的《费曼导读·四对齐机制 v1.0》同源，但**结论不同**：视频域的失效点在「基线率」，不在「架构」；在「特异性」，不在「灵敏度」。所有数字均可用一条命令复现，所有公式均可手算复核。

## 0. 一句话版本

**视频验收的省钱不是「少抽几帧」，是「知道自己抽的帧值不值钱」。而「值不值钱」只由一件事决定：你的验证器在低基线率下的特异性（Sp）。**

没校准过 Sp 就宣布减抽卡，是把运气记成了利润。

## 1. 为什么视频验收特别容易「假省钱」

「假省钱」不是骗子行为，它几乎是行业默认状态。原因有四层，一层比一层深。

### 1.1 第一层：抽卡的成本是可见的，漏检的成本是不可见的

生成 100 条候选花掉的 GPU 钱，账单会来找你；而「其中 3 条其实不合格却被放过去了」，账单不会来找你——它会在三个月后以「广告转化率不达标」「客户投诉画面穿帮」的形式出现，而那时已经没人把它和验收环节联系起来。

**可见成本 vs 不可见成本**，是所有质量岗位的结构性困境。它以最隐蔽的方式奖励「放松验收」：放松的人当月省了钱，出事的人三个月后才出现，往往还不是同一个人。

### 1.2 第二层：视频的缺陷是「时间局部」的，而抽帧是「时间均匀」的

一段 300 帧的视频，瑕疵可能只占 2%（约 6 帧：一次手指穿模、一次文字跳动、一次镜头跳切）。均匀抽 20 帧，命中这 6 帧的概率并不高；而人的直觉恰恰相反——**「我抽了 20 帧都没问题」会被当成「整条片子没问题」**。

这是典型的采样偏差被误读成总体结论。用统计的语言说：你把「样本中未观察到缺陷」当成了「总体中不存在缺陷」，而这两者的差距，恰好由缺陷的**持续时间占比**与**样本量**共同决定。

### 1.3 第三层：验证器的「准确率」是个会骗人的词

一个人说「我的模型准确率 95%」，听起来很强。但在基线率 8% 的场景里，「95% 准确率」可能意味着：它把大量坏样本判成好样本——因为**坏样本本来就少，全判「好」也能拿到 92% 的准确率**。

这是本文最重要的一个洞见，也是分仓存在的理由：**在低基线率下，准确率（accuracy）几乎是一个无信息的指标，真正决定经济性的是 PPV（判为好的样本里，真的好占多少）**。

### 1.4 第四层：减抽卡的宣称没有对拍习惯

多数团队宣布「我们把抽检从 20 帧降到 5 帧」，依据是「感觉没漏」。而「感觉没漏」在统计上等价于「我没有观察到漏」——这不是证据，是样本量不足。

主仓的四对齐要求「每个数字有出处」；在视频域，这条要求具体化为：**减抽卡倍数必须有 held-out 校准，且必须写明基线率 q 与验证器的 Se/Sp**。缺任何一项，这个倍数就是宣传。

### 1.5 四层困境的对照表

| 层次 | 表面现象 | 真实机制 | 常见错误对策 | 四对齐对策 |
|---|---|---|---|---|
| 成本可见性 | 「抽检越少越省钱」 | 漏检成本延迟出现且归因困难 | 压缩抽检量 | 把漏检成本写进成本函数 |
| 时间局部性 | 「抽了 20 帧都没事」 | 缺陷持续占比低 + 样本小 → 命中概率低 | 增加抽帧数（线性加钱） | 用变化点定位，只在可能处加密 |
| 指标误导 | 「准确率 95%」 | 低基线下 accuracy 被真阴性支配 | 追求更高 accuracy | 改看 PPV 与 Sp |
| 宣称无对拍 | 「体感没漏」 | 未观察 ≠ 不存在 | 靠经验背书 | held-out 校准 + 固定种子复跑 |

## 2. 四对齐在视频域的重定义

主仓的四轴是「结果 / 技术 / 代码 / 方向」。视频域不换轴，但每轴的**判据**必须换——因为这里的失效模式不一样。

| 轴 | 主仓判据（通用） | 视频域判据（本仓） | 为什么必须换 |
|---|---|---|---|
| 结果 | 数字有出处、可复跑 | 减抽卡倍数必须附 q、Se、Sp、种子、抽样规模 | 同一个倍数在不同 q 下经济含义完全不同 |
| 技术 | 机制有名字、输入输出、失效条件 | 必须说清「低基线下 Sp 主导」这一因果 | 否则读者会去优化 Se（错的方向） |
| 代码 | 命令真跑、exit code 契约 | 固定种子 + 零依赖 + 输出可对拍 | 蒙特卡洛不固定种子则数字不可复现 |
| 方向 | 三不全写 | 安全层永不让渡 + G8 域拒绝 | 视频合成是双用途，边界必须先于性能 |

### 2.1 为什么「结果轴」在视频域要加三个字段

因为一个孤立的「9.82×」是不可解释的。读者会问三个问题：**基线是多少？验证器多强？跑了多少次？**

- 基线 q=8% 时 9.82×，若 q=50%，同一验证器只有约 1.9×（因为分母变大，上限被压缩）；
- 验证器 Se/Sp 从 0.978/0.977 掉到 0.874/0.818，倍数从 9.82× 掉到 3.68×（掉 62%）；
- 蒙特卡洛 200,000 次抽样的标准误足够小，才敢报两位有效数字。

**换任何一个字段，倍数就变。** 所以「附三字段」不是形式主义，是让数字可被解释的唯一办法。

### 2.2 为什么「技术轴」要强调因果而不是公式

公式可以背，因果不能背。会背 `PPV = Se·q / (Se·q + (1−Sp)(1−q))` 的人很多，能说出「为什么在 q=8% 时把 Sp 从 0.977 降到 0.818 会让倍数腰斩」的人很少。而后者才是决策依据。

## 3. 对齐一：结果轴 —— 9.82× 的完整记录

### 3.1 记录格式（本仓标准）

| 字段 | 值 |
|---|---|
| 指标 | 生成端减抽卡倍数（期望生成数之比） |
| 值 | 9.82×（强验证器）/ 3.68×（平庸验证器） |
| 口径 | 期望生成数由 `1/q` 降至 `1/PPV`，倍数 = `PPV/q` |
| 基线率 q | 8%（困难提示词下的真实可接受率） |
| 验证器 Se / Sp | 0.978 / 0.977（强）；0.874 / 0.818（平庸） |
| 抽样规模 | 200,000 次蒙特卡洛 |
| 种子 | 20261016 |
| 复跑 | `python video_acceptance_ci.py`（约 30 秒） |
| 边界 | 模拟值，非生产实测；验证器 Se/Sp 为给定配置，真实管线须自行 held-out 校准 |

### 3.2 手算复核（不信任任何「跑出来的数」）

以强验证器为例，代入公式：

```
PPV = Se·q / (Se·q + (1−Sp)·(1−q))
    = 0.978×0.08 / (0.978×0.08 + 0.023×0.92)
    = 0.07824 / (0.07824 + 0.02116)
    = 0.07824 / 0.09940
    = 0.7871
倍数 = PPV / q = 0.7871 / 0.08 = 9.84
```

**手算 9.84，模拟 9.82。** 差 0.2%，来自 20 万次抽样的蒙特卡洛噪声——这个差本身就是诚实的一部分：如果两者完全相同到小数点后两位，反而说明有人把闭式解当成了模拟结果。

再看平庸验证器：

```
PPV = 0.874×0.08 / (0.874×0.08 + 0.182×0.92)
    = 0.06992 / (0.06992 + 0.16744)
    = 0.06992 / 0.23736
    = 0.2946
倍数 = 0.2946 / 0.08 = 3.68
```

手算与模拟**完全一致**（3.68）。为什么这一行能完全一致、上一行差 0.2%？因为 0.2946 恰好落在两位小数的稳定区间，而 0.7871 更敏感。**这也是一个教训：同一位有效数字在不同数值上的稳定性不同，报数时必须知道自己站在哪。**

### 3.3 「95% 准确率」的骗局解剖

假设有人宣称验证器「95% 准确」，并据此推算减抽卡 7.79×：

```
PPV(95%准确) = 0.95×0.08 / (0.95×0.08 + 0.05×0.92)
             = 0.076 / (0.076 + 0.046)
             = 0.623
倍数 = 0.623 / 0.08 = 7.79
```

而实际平庸验证器只做到 3.68×。虚高比例 = (7.79 − 3.68) / 3.68 = **+111.7%，约 +112%**。

这就是本仓 README 里那个「+112% 高估」的来源。它不是修辞，是一次可手算的算术事故：

| 宣称 | 依据 | 真实值 | 误差 | 后果 |
|---|---|---|---|---|
| 7.79× | 「我的验证器 95% 准确」 | 3.68× | +112% | 按 7.79× 排预算 → GPU 账单超支一倍以上 |
| 9.82× | held-out 校准后的 Se/Sp | 9.82×（模拟）/ 9.84×（手算） | ±0.2% | 可写进预算表 |

**这张表是分仓存在的全部理由**：不是「我们的数字更大」，是「我们的数字敢被手算」。

### 3.4 结果轴评分

| 项 | 判定 | 得分 |
|---|---|---|
| 有口径（q/Se/Sp/种子/规模） | 齐 | 5 |
| 有复跑命令 | 一条命令 | 5 |
| 有边界（模拟非实测） | 显式写明 | 5 |
| 有第三方手算路径 | 本文给出 | 5 |

**小计：5/5。** 自评必须给理由，理由就是上面四行——只写「5 分」等于没评。

## 4. 对齐二：技术轴 —— 为什么低基线下「特异性」是生死线

### 4.1 机制四件套

| 项 | 内容 |
|---|---|
| 名字 | PPV 校准（Positive Predictive Value calibration） |
| 输入 → 输出 | 验证器 (Se, Sp) + 基线率 q → 判为「好」的样本中真正好的比例 |
| 为什么有效 | 把「生成多少条才有一条能用」从盲目尝试变成可计算期望 |
| 失效条件 | ① q 估计错误；② Se/Sp 由非 held-out 数据得出；③ 分布漂移（模型换代/提示词风格变化） |

### 4.2 一个反直觉的数值事实

固定 Se=0.95，变化 Sp，看 PPV 在 q=8% 下的表现：

| Sp | PPV | 倍数（PPV/q） | 直觉上「准确率」看起来如何 |
|---|---|---|---|
| 0.999 | 0.988 | 12.35× | 几乎完美 |
| 0.99 | 0.892 | 11.15× | 很好 |
| 0.977 | 0.787 | 9.84× | 好 |
| 0.95 | 0.623 | 7.79× | 「95% 准确」听起来还行 |
| 0.90 | 0.452 | 5.65× | 一般 |
| 0.818 | 0.295 | 3.68× | 差 |
| 0.70 | 0.123 | 1.54× | 几乎没用 |

**关键观察**：Sp 从 0.977 降到 0.95（只降 2.7 个百分点），倍数从 9.84× 掉到 7.79×（掉 21%）。而在高基线率场景（q=50%）下做同样的变化，倍数只从约 1.90× 掉到约 1.82×（掉 4%）。

**结论**：**基线率越低，Sp 的边际价值越高。** 视频生成正是典型的低基线率场景（难提示词下 5%–15%），所以「优化 Sp」比「优化 Se」重要得多——这与多数人的直觉相反，多数人第一反应是「让它更会找出好的」。

### 4.3 为什么「优化 Se」是错方向

因为 Se 高只意味着「好的不漏」，而验收的经济损失主要来自「坏的漏过去」（假阳性放行）。在低基线下，假阳性的绝对数量由 `(1−Sp)×(1−q)` 支配——`(1−q)` 接近 1，所以哪怕 `1−Sp` 只有 5%，也会产生与真实好样本同量级的误放行。

用一句大白话：**坏样本本来就多（92%），你只要对坏样本稍微宽松一点，放过去的坏样本就会淹没真正的好样本。**

### 4.4 第二路机制：序贯抽帧（T2）

| 项 | 内容 |
|---|---|
| 名字 | 变化点触发的自适应抽帧（change-point triggered sampling） |
| 输入 → 输出 | 300 帧视频 + 一维廉价信号 → 需要人工/模型细看的帧清单 |
| 为什么有效 | 缺陷在时间上是局部突变，而廉价信号能在全时间轴上几乎零成本扫描；贵检查只在突变附近加密 |
| 失效条件 | ① 缺陷是「缓慢渐变」而非突变（如逐渐偏色）；② 廉价信号对该类缺陷不敏感；③ 缺陷时长极短但变化幅度小（低对比穿模） |

**实测**：均匀抽样需 149 帧达到 95% 命中置信度；自适应策略（15 帧稀疏基线 + 2 个变化点各 16 帧加密）= 47 帧，减至 **3.2×**。

算一下这个数的含义：149 → 47，省下的 102 帧如果每帧人工 8 秒，一条片子省约 13.6 分钟。一天 30 条片子，约 6.8 小时——**这才是「减抽卡」的真实现金流**，而不是「AI 让我们更先进了」。

### 4.5 两路机制的对照

| 维度 | T1 生成端（PPV 校准） | T2 验收端（变化点抽帧） |
|---|---|---|
| 省的是什么 | GPU 生成次数 | 人工/模型检查帧数 |
| 关键参数 | Sp（特异性） | 廉价信号的灵敏度 |
| 主要失效 | q 估错、分布漂移 | 缓慢渐变缺陷 |
| 校准方式 | held-out 含对抗样本 | 缺陷库覆盖度 |
| 单位经济 | 元/条（生成成本） | 分钟/条（人力成本） |
| 共同前提 | 没有校准就没有宣称 | 同左 |

## 5. 对齐三：代码轴 —— 一条命令的契约

### 5.1 契约内容

| 项 | 承诺 |
|---|---|
| 命令 | `python video_acceptance_ci.py` |
| 依赖 | 仅标准库（零第三方） |
| 运行时长 | 约 30 秒 |
| 随机性 | 固定种子 20261016，输出确定 |
| 网络 | 不需要 |
| 退出码 | 成功 0，输出为 stdout |
| 副作用 | 无文件写入 |

### 5.2 为什么「固定种子」是契约而不是细节

因为不固定种子的蒙特卡洛，读者跑出来的数和你写的不一样。这不会被认为是「随机噪声」，会被认为是「你在编数」。

**一条铁律**：**凡对外发布的随机实验，种子必须写在命令旁边，且必须是真的被用上的那个种子**。写了种子但代码里没用，比不写更坏——它给出虚假的可复现承诺。

### 5.3 输出对拍的方式

```
$ python video_acceptance_ci.py
... 强验证器 9.82× / 平庸验证器 3.68× / 抽帧 149→47 ...
$ echo $?
0
```

读者不需要信任作者，只需要跑一次比对。**把验证权交出去，是唯一能换来信用的动作。**

## 6. 对齐四：方向轴 —— 安全层永不让渡

### 6.1 三条硬绑定（本仓原文的忠实转述）

1. **L1 安全层（深度伪造/IP/违禁内容检查）永不参与减抽卡**——安全帧永远全查。
2. **held-out 校准集必须包含对抗性安全样本**——只在良性样本上校准的验证器是负债，不是资产。
3. **涉及武器、恶意软件、未授权监控等双用途致命域的用途，整体出界**（主仓 G8 闸）。

### 6.2 为什么这三条必须写进「导读」而不是附录

因为导读决定读者怎么用。一个只读导读的人，会以为「这是省钱工具」，然后把它接到一个不该省的环节上——比如把安全审核也纳入抽样。

**方向轴的职责就是把「不能省的地方」放在读者最先看到的位置。** 省钱的诱惑是即时的，边界的记忆是延迟的；不写在前面，就等于没写。

### 6.3 双用途的具体形状

| 场景 | 属于本仓范围？ | 理由 |
|---|---|---|
| 广告片、短剧、MV 的成片验收 | 是 | 纯验收，不生成 |
| 生成端候选筛选（自家模型） | 是 | 成本优化 |
| 换脸视频的「质量验收」 | 视上游合法性而定 | 验收本身中性，但上游若为未授权换脸则整体出界 |
| 教模型如何绕过内容审核 | **否** | 属于规避安全机制 |
| 生成可用于误导公众的合成新闻画面 | **否** | G8 |
| 武器/监控相关合成内容的「质量评估」 | **否** | G8，无例外 |

**判据一句话**：本仓只回答「这条片子够不够好」，从不回答「怎么让它更真/更骗得过人」。

## 7. 十四个例子：同一套尺子量十四种视频场景

### 7.1 例一：电商主图短视频（15 秒，产品特写）

- 结果：缺陷多为「文字贴图抖动」「产品边缘穿模」，持续 0.3–1 秒。
- 技术：变化点检测对这类突变极敏感，T2 收益最大。
- 代码：可套用本仓参数，缩短窗口。
- 方向：不涉及安全边界。
- 四对齐结论：**T2 收益 > T1 收益**（生成端已用固定模板，q 本来就高）。

### 7.2 例二：AI 短剧（单集 3 分钟，多镜头）

- 结果：缺陷集中在「角色一致性」（同一人不同镜头脸变）与「口型对齐」。
- 技术：角色一致性是**跨镜头**问题，单帧抽检抓不到；必须做跨片段嵌入比对。
- 代码：需要额外的嵌入模型，超出本仓零依赖范围。
- 方向：短剧常涉及真人形象授权，属 IP 边界。
- 四对齐结论：**本仓机制必要但不充分**——跨镜头缺陷需要新机制，且必须明确写出「本仓不覆盖」。

### 7.3 例三：品牌 TVC（30 秒，高预算）

- 结果：预算高、容错低，验收成本占比可忽略。
- 技术：这类场景应「全检」而非「减抽卡」。
- 代码：本仓仍可用于生成端筛选。
- 方向：品牌安全优先于省钱。
- 四对齐结论：**减抽卡不是普适目标**。在高价值、低容错场景，正确的四对齐结论是「不用」——这是方向轴的高分用法。

### 7.4 例四：MV（音乐视频，风格化强）

- 结果：风格化画面导致「缺陷」定义模糊（是穿模还是艺术处理？）。
- 技术：不变量难设，因为「应该是什么样」本身不唯一。
- 代码：可跑，但结论需人判。
- 方向：明确「本工具不判美学」。
- 四对齐结论：**技术轴的失效条件必须是「不变量无法形式化」**。这类场景里，诚实的答案是「本方法不适用」。

### 7.5 例五：口播数字人（长时间固定机位）

- 结果：缺陷多为嘴部抖动、眼神漂移、字幕错位。
- 技术：固定机位使背景差分极其便宜，变化点检测性价比最高。
- 代码：可显著减少人工帧。
- 方向：数字人涉及肖像与声音授权。
- 四对齐结论：**这是 T2 的最佳场景**（结构性稳定 = 不变量好设）。

### 7.6 例六：多语言配音版（同画不同音）

- 结果：缺陷是音画不同步、口型与音素错配。
- 技术：需要音频侧信号，不在本仓一维视觉信号范围内。
- 代码：本仓可复用框架但需扩展输入。
- 方向：配音授权与二次创作边界。
- 四对齐结论：**扩展点必须写明**：本仓只处理视觉时间轴。

### 7.7 例七：动漫/二次元（高帧率、运动幅度大）

- 结果：夸张变形是常态，误报率高。
- 技术：需要引入「风格容忍度」，否则 Sp 崩塌。
- 代码：参数需重标定。
- 方向：无特殊安全风险。
- 四对齐结论：**Sp 崩塌会直接吃掉全部收益**——这正是第 4.2 节那张表的现实版。

### 7.8 例八：直播切片（海量、低单条价值）

- 结果：单条价值低，人工成本占比极高。
- 技术：批量预处理 + 只对高风险片段抽检。
- 代码：需流水线化，本仓原型可直接嵌。
- 方向：切片涉及主播肖像权。
- 四对齐结论：**单位经济决定策略**：低价值场景用「粗筛 + 高召回」而非「精准」。

### 7.9 例九：AI 转绘/风格迁移（画面整体变化）

- 结果：整体风格变化让「异常」与「风格」难分。
- 技术：需以源视频为参照做结构对齐。
- 代码：框架可复用，判据需新增。
- 方向：涉及原作版权（衍生作品边界）。
- 四对齐结论：**参照系的选择本身就是技术轴的一部分**——没有参照，异常无定义。

### 7.10 例十：长片（90 分钟）

- 结果：帧数巨大，均匀抽检的命中率趋近于零。
- 技术：必须分层（场景级 → 镜头级 → 帧级）。
- 代码：本仓单条视频逻辑需外层调度。
- 方向：发行级审查另有合规要求。
- 四对齐结论：**单层抽检在长片上失效**，这是规模效应，不是参数问题。

### 7.11 例十一：UGC 内容审核（合规优先）

- 结果：目标是「不漏」，不是「省钱」。
- 技术：高召回策略，允许高误报。
- 代码：本仓可用于成本估算，不可用于决策。
- 方向：**这是安全层，永远全查**。
- 四对齐结论：**本仓明确不适用于此场景**，因为这里的优化目标与减抽卡相反。

### 7.12 例十二：虚拟人直播（实时）

- 结果：延迟敏感，离线抽帧不可用。
- 技术：需流式检测，本仓为离线原型。
- 代码：不可直接套用。
- 方向：实时场景的失败代价更高。
- 四对齐结论：**「不可用」也要写清楚**，否则读者会硬套然后失败，再把失败归因于方法。

### 7.13 例十三：内部评审（无商业压力）

- 结果：无预算约束，抽检可随意。
- 技术：可用本仓做「评审一致性」研究。
- 代码：可跑。
- 方向：内部数据不对外。
- 四对齐结论：**四对齐在内部场景可以降级**，但「结果轴」不能省——否则内部结论无法迁移到外部。

### 7.14 例十四：本仓自己

- 结果：9.82× / 3.68× / 3.2×，全部可复跑、可手算。
- 技术：PPV 校准 + 变化点抽帧，各有失效条件。
- 代码：一条命令，固定种子，零依赖，exit 0。
- 方向：三重安全绑定 + G8 出界声明。
- 四对齐结论：**自评 4.75**：结果 5、技术 4.5（跨镜头缺陷未覆盖）、代码 5、方向 5。扣分原因写在括号里——这就是自评该有的样子。

## 8. 六条联想（借什么、不借什么）

### 8.1 抽检标准 AQL（ANSI/ASQ Z1.4 传统）

**借用**：工业界早就有「按批抽检 + 可接受质量水平」的成熟体系，核心思想与本仓一致——**抽检方案必须由风险决定，不能由感觉决定**。
**不借**：不借它的「批」假设。视频不是同质批次，每条片子的缺陷分布都不同，AQL 的批量模型在这里会高估稳定性。

### 8.2 瓦尔德序贯概率比检验（Wald, 1945）

**借用**：「边看边决定是否继续采样」比「固定样本量」更省——这正是 T2 自适应抽帧的统计学祖先。
**不借**：不借它的强分布假设。视频缺陷不是独立同分布，序贯方法的最优性在此不成立，只能借「思想」不能借「最优性证明」。

### 8.3 休哈特控制图（Shewhart, 1931）

**借用**：把「正常波动」与「异常突变」分开，是变化点检测的工程原型。
**不借**：不借它的稳定过程假设。生成模型换代会让「正常」整体漂移，控制限必须重算。

### 8.4 误报与漏报的成本不对称

**借用**：医疗诊断里「宁可误报不可漏报」或反之，取决于两类错误的代价比。视频验收同理：广告片漏检的代价 >> 多查 20 帧的代价。
**不借**：不借医疗的具体阈值。代价比必须按场景重算，不能照抄。

### 8.5 古德哈特定律（Goodhart, 1975）

**借用**：一旦「减抽卡倍数」成为 KPI，团队就会去调参刷倍数，而不是提升真实质量。
**不借**：不借它否定度量。正确做法是**同时公布 Sp 与漏检率**，让单一指标无法被单独优化。

### 8.6 希波克拉底「首先，不要伤害」（primum non nocere）

**借用**：安全层永不让渡，是这条古老准则在工程上的直接翻译。
**不借**：不借它走向「什么都不做最安全」的保守主义。不发布也是一种伤害——它让需要工具的人没有工具。

## 10. 四种失败模式（视频域专属）

### 10.1 过拟合自家数据

用自家历史数据算 Se/Sp，再用同一批数据宣称倍数。**这不是校准，是记忆。**
对策：held-out 必须按时间切分（用旧数据校准、新数据验证），不能随机切分——随机切分会把同一批片子的相似帧分到两边，虚高 Sp。

### 10.2 安全层被当成「可配置项」

一旦安全层可以被参数关掉，它迟早会被关掉——因为关掉能省钱，而后果延迟出现。
对策：安全层不进配置，写死在代码路径上，且不提供关闭开关。

### 10.3 PPV 幻觉

用 accuracy 冒充 PPV，或用「验证器很准」代替具体 Se/Sp。
对策：任何对外数字必须附三字段（q/Se/Sp），缺一不得发布。

### 10.4 抽帧漏检的沉默失败

抽检通过但实际有缺陷，且没人发现——这是最危险的一类，因为它不产生任何告警。
对策：定期做「注入缺陷」的盲测（往样本里塞已知缺陷，看抽检能否抓到），把沉默失败变成可观测信号。

## 12. 与 Star 互推、「上热门保证」的关系

### 12.1 为什么分仓更容易被 star

因为它离钱近：一个「省 GPU 账单」的工具，比一个「判抄袭的协议」更容易让读者当场产生动作。所以分仓的导读第一屏必须写钱，而不是写架构。

### 12.2 互推的正确姿势

主仓回答「凭什么信这套尺子」，分仓回答「这套尺子能省多少钱」。两者是**内容互补**，不是**数字互换**。

本仓明确：**不做 star 交换、不刷量、不买推荐**。理由与主仓一致——star 是唯一能反映真实需求的信号，污染它等于自断反馈回路。

### 12.3 「上热门保证」的边界

平台算法不可控，所以任何「保证上热门」的表述都是不可证伪的宣传。本仓只承诺自己能控制的部分（见 README 的 Trending Pledge 段）：数字可复跑、问题 48 小时内回应、被证伪七日内更正、不达标可退星。

## 13. 补充：预算受限下的抽检设计（成本函数）

真实团队的问题从来不是「哪个方法更先进」，而是「这个月只有 500 元 GPU 预算、40 小时人工，怎么分配」。

把两路成本写成一行：

```
总成本 = C_gen × E[生成次数] + C_frame × 需检查帧数
```

代入本仓数据（假设 C_gen = 0.35 元/条，C_frame = 0.15 元/帧）：

| 策略 | 生成次数 | 检查帧数 | 总成本 | 相对基准 |
|---|---|---|---|---|
| 无验证器（盲抽） | 12.5（1/q） | 149 | 12.5×0.35 + 149×0.15 = 26.73 | 基准 |
| 平庸验证器 + 均匀抽帧 | 3.4（1/0.2946） | 149 | 1.19 + 22.35 = 23.54 | −12% |
| 强验证器 + 均匀抽帧 | 1.27（1/0.787） | 149 | 0.44 + 22.35 = 22.79 | −15% |
| 强验证器 + 自适应抽帧 | 1.27 | 47 | 0.44 + 7.05 = 7.49 | **−72%** |

**这张表推翻了一个常见直觉**：生成端优化（T1）在总成本里只占小头，验收端（T2）才是大头。因为帧检查是**逐帧线性成本**，而生成是**按条成本**。

所以正确的优先级是：**先修 T2，再修 T1**。这与「AI 时代要先优化生成」的流行叙事相反，但与账单一致。

## 14. 补充：多人评审的一致性（Kappa）

自动化之外，视频验收仍大量依赖人。两个人看同一条片子，结论不一致是常态——而「不一致」本身是质量信号：**它说明判据没被定义清楚**。

用 Cohen's Kappa 衡量（κ = 观察一致率扣除随机一致后的净值）：

| κ 区间 | 解读 | 该做什么 |
|---|---|---|
| < 0.4 | 判据基本没共识 | 停下来写判据，不要继续验收 |
| 0.4–0.6 | 中等一致 | 补样例库，逐条对齐边界 |
| 0.6–0.8 | 较好 | 可上线，定期抽检复盘 |
| > 0.8 | 高度一致 | 可考虑固化规则、部分自动化 |

**为什么这条要写进导读**：因为它解释了「为什么自动化前必须先做人工一致性」——如果人对「什么算缺陷」都没共识，任何自动化的 Sp 都是假的，它只是在拟合某个人的偏好。

## 17. 补充：怎么用 200 条样本估出可信的 Se/Sp（含区间）

「去做 held-out 校准」是正确的话，也是没用的话——因为它没告诉你**要多少样本**。这一节给出可执行的做法。

### 17.1 为什么必须给区间而不是给点估计

你在 200 条样本上测出 Sp = 0.975，这不等于真实 Sp 就是 0.975。抽样有误差，真实的 Sp 可能落在某个区间里。而在低基线率场景，Sp 的微小差异会放大成倍数的巨大差异（见第 4.2 节），所以**只报点估计是在制造虚假的精确感**。

用 Wilson 区间（比正态近似更稳，尤其在 p 接近 1 时）：

```
样本量 n = 200，观测 Sp = 0.95，95% 置信区间 ≈ [0.910, 0.973]
```

换成决策语言：

| 你想区分的东西 | 200 条样本够不够 | 说明 |
|---|---|---|
| 0.977 与 0.818（强 vs 平庸） | **够** | 差距 16 个百分点，远大于 ±3 的区间宽度 |
| 0.977 与 0.99 | **不够** | 差距 1.3 个百分点，落在噪声里 |
| 0.99 与 0.999 | **远不够** | 需要上千条，且阳性样本要足够多 |

**这条结论很实用**：如果你的目标只是「别用平庸验证器」，200 条样本足够；如果你要宣称「我的验证器接近完美」，200 条样本只会让你说出一个自己都不该信的数。

### 17.2 样本怎么选才不算作弊

| 做法 | 是否合格 | 原因 |
|---|---|---|
| 全部从最近一周取 | 否 | 同批分布，等于自测 |
| 按时间切分（旧校准、新验证） | 是 | 唯一能检验漂移的切法 |
| 随机切分 | 部分合格 | 同一片子的相邻帧会跨集泄漏 |
| 只取良性样本 | **否** | 安全层失效，Sp 虚高 |
| 含对抗样本（故意做的边界案例） | 是 | 分仓硬性要求 |
| 只取「明显成功/明显失败」 | 否 | 中间地带才是真正难判的 |

最后一条值得强调：**校准集的难度决定校准结果的可信度**。全用「一眼就知道」的样本，任何验证器都能拿到 0.99——但那 0.99 只在「一眼就知道」的分布里成立，而生产中的样本恰恰是那些「不太确定」的。

### 17.3 校准的最小闭环（四步，一步不能省）

1. **定判据**：什么算「不可接受」（必须可被两个人独立判出一致结论，κ ≥ 0.6）。
2. **切时间**：旧数据校准、新数据验证，中间留一段缓冲期防泄漏。
3. **算区间**：报点估计 + 置信区间，区间宽到无法区分两个方案时，说明样本不够，不许硬下结论。
4. **记边界**：写下「本次校准不覆盖哪些内容类型」，三个月后重校。

第 4 步是最常被跳过的一步，也是漂移事故的唯一防线。

## 18. 补充：从原型到生产的五道关

原型能跑通，只是证明了机制成立；离「能上线」还有五道关。每一道关都对应一个四对齐轴的失效。

### 18.1 第一关：数据切分关（对应结果轴）

**问题**：校准集与验证集是否真的独立。
**检验**：把验证集的片子拿去问「这条在训练时见过吗」，若有任何一条见过，结果作废。
**失败后果**：倍数虚高，且虚高幅度无法估计——这是最坏的一类错误，因为你连自己错了多少都不知道。

### 18.2 第二关：漂移监控关（对应技术轴）

**问题**：生成模型换代后，原来的 Sp 还成立吗。
**检验**：每月用固定的一小批「黄金样本」重测 Sp，画趋势线；Sp 下降超过 3 个百分点即触发重校。
**失败后果**：模型升级后验收标准悄悄失效，而团队以为一切正常——沉默失败的典型形态。

### 18.3 第三关：注入缺陷盲测（对应结果轴的「沉默失败」）

**问题**：抽检没报问题，是真的没问题，还是没看到。
**检验**：定期往待检流里注入已知缺陷（数量与类型保密），统计抓出率。抓出率低于设定值即停工排查。
**失败后果**：这是唯一能把「沉默」变成「信号」的手段。没有它，验收系统的可靠性完全不可测。

### 18.4 第四关：成本回收关（对应方向轴）

**问题**：为了做到这些校准与监控，投入的人力是否小于省下的钱。
**算法**：`回收周期 = 校准+监控的月成本 / 每月省下的 GPU+人工成本`。本仓成本函数（第 13 节）可直接套用。
**失败后果**：为了省钱而建的体系，成本超过省下的钱。这不是技术失败，是设计失败——它说明选错了场景（例如单条价值极低的长尾内容）。

### 18.5 第五关：回滚关（对应代码轴）

**问题**：新策略上线后出问题，多久能退回旧策略。
**检验**：演练一次「关掉自适应抽帧、回到全检」，记录耗时。超过 1 小时则不合格。
**失败后果**：没有回滚的系统不是自动化，是单点故障。而视频流水线通常是「一条卡住全线停」的结构。

### 18.6 五关与四轴的映射表

| 关 | 主要对齐轴 | 一句话判据 | 典型失败信号 |
|---|---|---|---|
| 数据切分 | 结果 | 验证集真的没见过 | 倍数漂亮但上线即掉 |
| 漂移监控 | 技术 | Sp 有趋势线 | 换代后突然不漏了 |
| 注入盲测 | 结果 | 能抓到已知缺陷 | 永远零缺陷报告 |
| 成本回收 | 方向 | 回收周期 < 6 个月 | 越省钱越贵 |
| 回滚 | 代码 | 1 小时内可退回 | 出事只能等修复 |

**这张表可以直接当上线评审清单用。** 五关全过再谈「减抽卡倍数」，顺序不能颠倒——因为没有前四关，第五关的倍数没有意义。

## 19. 补充：一个完整的验收日志长什么样

真实系统里，最容易被忽略的工件是**日志**。没有日志，四对齐里的「结果轴」在三个月后就会失去证据——因为当时算数的代码还在，但当时的输入分布已经不在了。

一份够用的验收日志，最小字段如下：

| 字段 | 例子 | 为什么必须有 |
|---|---|---|
| 时间戳 | 2026-10-19T14:03:22+08:00 | 对齐漂移分析的时间轴 |
| 内容类型 | 口播数字人 | 不同行收益差 5 倍以上（第 15 节） |
| 视频标识 | hash 前 12 位 | 可回溯，且不泄露原始文件 |
| 验证器版本 | v1.3.2 + 校准批次号 | 换验证器后旧结论不可混用 |
| q 估计 | 0.083（近 30 天滚动） | 倍数解释的分母 |
| Se / Sp（当次校准） | 0.978 / 0.977（批次 B7） | 倍数的分子 |
| 抽帧策略 | 稀疏 15 + 2 变化点 × 16 | 复算帧数 |
| 判决 | PASS（3 处可疑已人工确认） | 结论 |
| 人工复核人 | ID（脱敏） | 责任可追溯 |
| 耗时 | 生成 12.4 s / 检查 3.1 min | 成本函数输入 |

**为什么列这么细**：因为「三个月后有人问『当初那个 9.82× 是怎么来的』」是必然会发生的。到那时，能回答这个问题的不是记忆，是日志。而一份没有 q 与 Sp 的日志，等于什么都没记。

## 20. 补充：三类人的读法（同一份文档，三种入口）

同一份导读，读者会分成三类。四对齐要求「第一屏对三类人都不撒谎」，但不必对三类人都详尽。

| 读者 | 他只关心一句 | 应该给他什么 | 不该给他什么 |
|---|---|---|---|
| 决策者（要不要用） | 「这能省多少钱、风险多大」 | 第 13 节成本表 + 第 6 节边界 | 公式推导 |
| 工程师（怎么接） | 「命令是什么、参数在哪」 | 第 5 节契约 + 复跑命令 | 商业论证 |
| 评审者（能不能信） | 「数怎么来的、边界在哪」 | 第 3 节手算 + 第 10 节失败模式 | 宣传语 |

**一个具体的排版建议**：把这三类人的入口写在 README 首屏的三行里（「省钱 → 看 X」「接入 → 跑 Y」「质疑 → 算 Z」）。这比任何「架构总览图」都有用，因为它把选择权交给了读者，而不是强迫所有人按作者的顺序阅读。

## 21. 补充：三个反对意见，与我们的回应

一份机制文档如果不写「有人会怎么反对」，它就只完成了一半。以下三条是最常见的反对，回应尽量给数，不给态度。

### 21.1 反对一：「我的场景基线率高，这套没用」

**部分成立。** T1 的收益确实随 q 上升而压缩：同一台验证器，q=8% 时 9.84×，q=30% 时只有约 3.3×，q=50% 时约 1.9×。所以如果你的候选本来就有半数能用，生成端没什么可省的——这一点我们不辩解。

**但两件事仍然成立**：
1. T2 与 q 无关。帧检查的成本由缺陷持续时长与置信度要求决定，与生成端基线率没有关系。而第 13 节已经算过，T2 往往才是成本大头。
2. q 高时，对 Sp 的要求反而更低——因为假阳性的分母 `(1−q)` 变小了。所以高基线率场景做校准更便宜，不是更没必要。

**结论**：不是「这套没用」，是「这套的收益结构在你的场景里换了位置」。若有人拿这句话否定整套方法，那是把 T1 当成了全部。

### 21.2 反对二：「校准太麻烦，我们没这个人力」

**成立，但代价要算清。** 一次最小校准：200 条样本、两人独立标注、半天时间、一份区间报告。成本约 1 人日。

而一次「倍数虚高 112%」的事故成本：按 7.79× 排的预算，实际只能做到 3.68×，等于 GPU 支出翻倍。若月生成预算是 5000 元，多花的就是 5000 元左右——**远超 1 人日的成本**。

**但也要说清反面的情形**：如果月生成预算只有 200 元，1 人日的校准确实不划算。这时正确的答案不是「不做校准」，而是「不做减抽卡」——因为没有校准的减抽卡，省下的钱本来就不存在。

### 21.3 反对三：「你也在推销一套方法，凭什么信你」

**这条最该被认真对待。** 我们的回应分三层，且标明每层的证据强度：

| 层 | 内容 | 证据强度 |
|---|---|---|
| 可跑 | 一条命令、固定种子、30 秒出结果 | **强**：你可以自己跑 |
| 可算 | 9.82× 可由贝叶斯公式手算复核（第 3.2 节） | **强**：你可以自己算 |
| 可用 | 有团队在生产里因此省下成本 | **弱/未知**：本仓没有这类数据，不宣称 |

第三层我们明确写「未知」。这不是谦虚，是四对齐的硬要求——**没有证据的层，不许写成有证据**。如果一份文档在第三层也说得斩钉截铁，那它前两层的可信度也该被打折，因为作者没有区分「我知道」与「我希望」。

### 21.4 反对四：「开源了，别人抄走怎么办」

**会抄走，而且我们允许。** 许可证是 MIT，明确允许商用与闭源再分发，前提是保留署名。

那为什么还要发？因为这套东西的价值不在代码，在两样不可下载的东西上：
1. **校准过的数据**——你的验证器在你的内容分布上的 Se/Sp，别人抄不走；
2. **缺陷库**——你积累的「什么算不可接受」，是半年标注换来的，别人抄不走。

代码是配方，数据是资产。把配方公开换信誉，把资产留在手里换利润——这是本仓的取舍，也是主仓「逆转模式」里写的同一个判断：**暴露面是被管理的资产，不是被恐惧的漏洞**。

至于「有人拿它去做不该做的事」：那是 G8 的问题，不是开源的问题。G8 的答案写在文档第一页，而不是靠藏起代码来防止误用——**藏起来的代码防不住恶意，只挡得住善意**。

还有一层更实际的考虑：这类工具的真正竞争对手不是「抄你代码的人」，而是「你们团队内部那个拍脑袋的验收习惯」。公开一套可复跑的方法，首先改变的是自己的流程，其次才是别人的。**先让自己没法再靠感觉糊弄，这是开源自带的最强约束。**
